## Cost (the main Pipe B finding on this corpus)

Mean tokens per request and $ per 1,000 requests at list prices. **Warm** = high traffic, the system
prompt is read from cache every time; **cold** = requests rarer than the 5-min cache TTL, every one
re-writes the cache (1.25× input). `eval/score.py` computes both (`cost_profile` in `table3.json`).

| Model | Pipe A prompt / output tok | Pipe B prompt / output tok | $/1k warm A → B | $/1k cold A → B |
|---|---|---|---|---|
| Haiku 5.5 | 14,179 / 8,947 | 6,889 / 757 | $4.62 → $0.46 (**10.0×**) | $6.24 → $1.24 (5.0×) |
| Sonnet 5.5 | 14,179 / 2,013 | 6,889 / 284 | $23.14 → $4.40 (**5.3×**) | $55.52 → $20.01 (2.8×) |
| Opus 5.5 | 14,179 / 1,115 | 6,889 / 263 | $25.52 → $7.02 (**3.6×**) | $93.09 → $39.60 (2.4×) |
| Opus 5.5 `bare` (A only) | 1,088 / 3,482 | — | $70.25 (10× Pipe B Opus) | $74.98 |

- **The gap widens with usage frequency.** Caching makes the prompt nearly free for both pipes, so
  once traffic keeps the cache warm the bill is mostly output tokens (65–97% of warm cost), and
  Pipe A writes 4–12× more of those (the full plan plus the reasoning behind it). Translating a
  request is a short, fixed-shape answer.
- **Pipe B's cost is flat across instances; Pipe A's depends on the request.** Output tokens, SAT vs
  UNSAT: Pipe A Opus 1,707 vs 555, Haiku 13,417 vs 4,726 (a SAT answer needs a whole plan); Pipe B
  Opus 276 vs 251, Haiku 786 vs 730. Real traffic is mostly SAT, so Pipe A's real-world mean is above
  the corpus mean, and longer horizons / larger catalogs grow Pipe A's prompt and plan but not Pipe B's spec.
- The solver's own cost is ~0.3–0.5 s of local CPU per request (CP-SAT); it is not an API cost.
- Pipe B prompt = ~3.7k tokens of instructions + code list and ~2.5k of JSON schema (the module-code
  enum, defined once via `$defs`; inlined it cost ~9k more). Both are cached.

## Notes
- **Superseded first sweep** (`eval/runs/pipe_b_v1_enumbug/`, $0.46): the spec's code enum held only
  the 129 schedulable modules, so `preclusion_deadend` ("I have already completed CS1010") was
  inexpressible (CS1010 exists only in `preclusions.yaml`). All three models scored 34/35 there and
  each correctly quoted the request under `unsupported_requests` instead of dropping it silently.
  Fixed (`held_code` enum = modules + preclusion-only codes) and guarded by
  `tests/test_pipe_b.py::test_every_gold_spec_is_expressible_in_the_schema`; all rerun.
- Haiku lists the closing question ("Can it be done, and if so what is my plan?") under
  `unsupported_requests` on 7/35; harmless (graded fields are exact), Sonnet/Opus never do.
- Implication: like Pipe A `full`, the translator is at ceiling on auto-draft prompts. They name every
  knob in fixed phrasing, so translation is close to dictation. Pipe B vs Pipe A `full` will only
  separate on accuracy with hand-authored, implicit prompts (B7); today they separate on cost (above),
  and Pipe B beats Pipe A `bare` on both accuracy (100% vs 0% valid plans) and cost.
